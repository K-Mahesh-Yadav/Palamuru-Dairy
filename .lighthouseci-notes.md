# Why the SEO category is asserted at 0.92, not 1.0

Lighthouse's `robots-txt` audit fetches `/robots.txt` **from the page's own
JavaScript context**. This site sends `connect-src 'none'`, which is exactly
the directive that governs page-initiated fetches — so Lighthouse's probe is
refused and the audit scores 0, dragging the SEO category to 0.92.

The file itself is fine. Verified in production:

    curl -sI https://palamuru-dairy.vercel.app/robots.txt   -> 200, valid body

**Real crawlers are unaffected.** Googlebot requests `robots.txt` as a direct
top-level HTTP request. CSP governs a _document's_ subresource loads, not an
external agent's own HTTP calls, so it never applies.

## Do not "fix" this by relaxing connect-src

Changing `connect-src 'none'` to `'self'` would make the audit pass. It would
also trade a real defence-in-depth control for a number in a report. This site
makes no network requests at all — no form, no analytics, no third-party
embeds — so `'none'` is both correct and free. Keep it.

`robots-txt` is switched off as an individual assertion and the category floor
is 0.92 so CI reflects reality. If the category ever drops _below_ 0.92,
something genuinely regressed and the build should fail.
